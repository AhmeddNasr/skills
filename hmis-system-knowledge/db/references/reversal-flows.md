# Reviewed cancellation and reversal paths

Source excerpts reviewed 2026-10-21; see schema-study-evidence.json. These are version-specific business operations, not authorization to execute them and not a generic hard-delete sequence.

| Module/action | Reviewed guards and downstream order | Consequence for a maintenance script |
|---|---|---|
| Allergy delete | Resolves the active transaction, delegates delete, appends PatientAllergyHistory with deletion reasons, then saves. | Deleting transaction/reactions alone bypasses history and patient allergy state. |
| Clinical-sheet edit/cancel/delete | Edit selects a draft; sign changes state/date; cancel selects a signed sheet and sets reason/comment/date; delete is separate IsDeleted change. ModifiedTS concurrency applies. | Preserve the distinction between abandoning a draft, cancelling a signed document and physical history removal. |
| Nursing cancel performed instance | Checks cumulative performed quantity, calls CPOE instance cancellation, conditionally cancels VM dispense/service when ServiceTransactionID exists, recalculates order status, then deletes local perform transaction with ModifiedTS. | Performed quantity, billing and local nurse state must agree; a local flag alone is incomplete. |
| LR cancel investigation | LAB path checks ModifiedTS and previous specimen-collected/received states. Notify-perform configuration chooses whether VM/CPOE quantity/state is reset to Ordered or retained InProgress; result-type/reset flags depend on previous state. Nonlab branch differs. | Cancellation behavior depends on specimen history and configuration, not only current LastStatusID. |
| OR cancel reservation | Checks allowed status transition and ModifiedTS; cancels CPOE order; invokes VM cancellation according to CallVisitManagement configuration; updates reservation cancellation state/reason/history only after successful responses. | Preserve reservation, order and service synchronization; do not implement as deleting the reservation row. |
| Dental delete | Reviewed DeletePatientProcedureTransaction allows the active planned/null-state path, rejects other nonplanned states, updates treatment-area visualization and writes audit. | Performed/in-progress procedures require their discontinue/complete cycle, not the planned-item delete method. |
| Physiotherapy remove session detail | Rejects performed sessions, completed orders, missing session/detail and removing the last detail; compares session/detail timestamps before soft delete. | Quantity and minimum-detail rules must remain; deleting an arbitrary detail can violate the session aggregate. |
| Blood unit return | Uses return eligibility/timing, order pending/in-progress state, blood source and reason. Purchase/donation/external return can cancel NAT service; patient-source return changes bag/transaction state and returns service/bank quantity. Discard paths differ. | Returning inventory is not the same as discarding or cancelling the clinical/billing quantity. |
| Finance journal reversal | Builds a posted automated reverse entry using original fiscal/account/cost-center/owner context and swaps debit/credit. Posted entry edit is restricted in reviewed save. | Preserve accounting history; direct deletion of journal details is not equivalent to reversal. |
| NPHIES claim cancel | Selects claim requests by visit/statement, sends external cancellation tasks, logs request/response errors and updates VM NPHIES status. | SQL deletion cannot retract the external request or prove payer acknowledgement. |
| CPG setup delete | Soft-deletes the plan's setup links, definition visits and needs. | This is master setup retirement, not cancellation of a patient encounter. |
| HSM room delete | Checks use/assignment, marks room deleted, deactivates assignments and specialties and calls ER/OR projection removal by classification. | Shared hospital setup is not an owned visit child. |
| Failed-message replay | Pending SHR rows under retry limit are republished; error-queue messages are persisted; process-local duplicate dictionary is used. | Do not replay automatically after deleting/correcting a target record without validating consumer idempotency and intended outcome. |

For packages, use core-flows.md and visit-evidence-study.md: cross-visit assignment/use and purchase-time snapshots require special checks. For VisitService.ServicePackageID the observed lineage is established, but the deployed assigning writer is still awaiting source-version confirmation. Do not label an exhaustive destructive script verified while that writer or another relevant effect is unresolved.
