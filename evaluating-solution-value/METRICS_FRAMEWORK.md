# Metrics and KPI Framework

Every feature must have defined success metrics. If a user cannot explain how a feature improves a metric, question why the feature is being built.

## 1. Quantitative Metrics (Hard Numbers)
These should be tracked via analytics dashboards or database queries.
*   **Conversion Rate:** Percentage of users who complete a desired action (e.g., checkout, signup).
*   **Task Completion Time:** How long it takes a user to perform a core workflow (e.g., reducing report generation from 2 hours to 5 minutes).
*   **Error Rate:** Frequency of system errors, crashes, or user input errors.
*   **Adoption Rate:** Percentage of total active users utilizing the new feature.
*   **Cost Savings:** Dollars saved by automating a manual process or reducing infrastructure costs.

## 2. Qualitative Metrics (Human Sentiment)
These are gathered via surveys, feedback forms, or interviews.
*   **Net Promoter Score (NPS):** "How likely are you to recommend this product?" (0-10 scale).
*   **Customer Satisfaction (CSAT):** "How satisfied were you with this specific interaction?"
*   **User Effort Score (UES):** "How easy was it to complete your task today?"

**Action:** When a user proposes a feature, ask them: "Which specific KPI will this improve, and what is our current baseline number?"
