# Agile User Story Template

You MUST format all functional requirements using this strict structure. Reject any requirement that cannot fit this model.

## The Format

`As a [persona/role], I want to [action/feature] so that [value/benefit].`

## Rules
*   **Persona:** Must be a specific user type (e.g., "Customer Support Agent", NOT "User").
*   **Action:** Must be a distinct, verifiable action.
*   **Value:** This is the most critical part. If the "so that" clause is weak or missing, the story has no business value and must be rejected.

## Example
*   **Bad:** The system needs a login button.
*   **Good:** As a returning customer, I want to securely log in with my email and password so that I can view my past order history.
