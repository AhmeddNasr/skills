# INVEST Framework for User Stories

You must evaluate every User Story against these 6 criteria. If a story fails ANY of these, reject it back to the user for refinement.

*   **I - Independent:** Can this story be developed, tested, and delivered on its own? Or is it hopelessly tangled with other stories?
*   **N - Negotiable:** Is the story a statement of need, rather than a rigid contract? Does it leave room for the developers to find the best technical solution?
*   **V - Valuable:** Does it deliver clear, measurable value to the end-user or the business? (Check the "so that" clause).
*   **E - Estimable:** Do the developers have enough information to guess how long this will take? (If it's too vague, it's not estimable).
*   **S - Small:** Can this be completed within a single sprint? If not, it is an Epic and must be broken down.
*   **T - Testable:** Are the Acceptance Criteria clear enough that a QA engineer can write a definitive pass/fail test for it?
