# AHJ Prelive patient migration

Approved target: AHJ-HMISDBTest1 / AHJ.Env.HCMS_prelive, UAT only. Real HMIS sign-in and current entity/environment revision are required. Preview never writes.

Patient workbook uploads automatically validate and insert compatible valid patient aggregates. The Excel `Code` is preserved. `IsActive` is true and `LastClassificationID` is null. Database-generated patient/address/contact identities are used; source IDs remain migration references.

The adapter inserts only MPI.Patient, MPI.PatientAddress, MPI.PatientContact and, when missing, MPI.SLKP_Country, MPI.SLKP_City and MPI.SLKP_Region. Country is resolved first, then city under that country, then region under that city. Existing active matches are reused. Ambiguity/inactive matches stop the aggregate rather than overwriting existing records. Nonidentity geographic IDs are allocated under transaction locks; patient identities are allocated by SQL Server.

Each patient, its related rows and new locations share a transaction. A failed aggregate rolls back, while other valid patients can commit. No existing patients are updated or deleted. Duplicate patient code/identification is rejected. Successful identities are checkpointed locally; retry skips committed source rows. SQL commit/local-checkpoint interruptions require reconciliation rather than blind retries.

The results workbook reports original patient code, generated patient ID and status. The correction workbook contains only failed patient input rows plus Errors, in a re-uploadable patient-template format. Already saved mappings are frozen. Other migration domains and patient relationships still require their own adapters. Direct SQL does not invoke HMIS patient registration code generation or publish its application message-broker events.

Excel repair fix: remove validation records with empty sqref, correct validation counts, and convert direct cross-sheet list formulas to named ranges. Live dependent lists use OFFSET with parent maps. Duplicate target names are shown with an ID selector and validated against the snapshot. New country/city/region names can be entered as free text.
